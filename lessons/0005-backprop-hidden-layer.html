Backpropagation, Part 2: The Hidden Layer

Lesson 4 got you dZ2, dW2, db2 — everything needed to update the output layer. But W1 and b1 still have no gradient. This lesson pushes the same chain rule one layer further back, through W2 and then through ReLU, to finish the backward pass. Once this is done, you'll have every gradient needed for one full training step.

Where the gradient signal is now

Recall the forward equations and what Lesson 4 already computed:

Z1 = X @ W1 + b1
A1 = relu(Z1)
Z2 = A1 @ W2 + b2      ← already have dZ2 = (P - Y) / batch, dW2, db2
P  = softmax(Z2)

To reach W1, the chain rule has to pass backward through two more functions: the matrix multiply A1 @ W2, and the ReLU inside A1 = relu(Z1). Two steps, two different kinds of operation — and that difference matters.

Step 1 — through the matmul: dZ2 → dA1

Same shape-reasoning trick as Lesson 4. Z2 = A1 @ W2 + b2, and we want dA1, which must have the same shape as A1.

QuantityShape
dZ2(batch, n_out)
W2(n_hidden, n_out)
A1, so dA1(batch, n_hidden)
Try it yourself first: what combination of dZ2, W2 (and transposes) gives shape (batch, n_hidden)? Then reveal 
dA1 = dZ2 @ W2.T
# (batch, n_out) @ (n_out, n_hidden) -> (batch, n_hidden)  ✓

Notice the pattern versus Lesson 4's dW2 = A1.T @ dZ2: same two matrices, same operation, but here it's the other one that gets transposed, because this time we're solving for the other side of the original multiplication. Whichever of A1 or W2 you're not computing the gradient for gets transposed and left-multiplied (or right-multiplied) against the incoming gradient — the shapes tell you which.

Step 2 — through ReLU: dA1 → dZ1

This step is different in kind. A1 = relu(Z1) is not a matrix multiply — it's an element-wise function, applied independently to every entry. So its backward step is element-wise too, not a matmul at all.

Try it yourself first: what is d(relu(z))/dz? Then reveal

relu(z) = max(z, 0). For z > 0, relu(z) = z, so the slope is 1. For z < 0, relu(z) = 0 — constant, slope 0. (At exactly z = 0 the function has a kink; the convention is to just pick 0 or 1 there, it never matters in practice.)

relu'(z) = 1  if z > 0
relu'(z) = 0  if z <= 0

A step function: it's a gate that either passes the incoming gradient through unchanged, or blocks it to zero — one decision per entry, independently.

By the chain rule, dZ1 is dA1 multiplied element-wise by that gate:

dZ1 = dA1 * (Z1 > 0)   # element-wise -- NOT @

(Z1 > 0) produces a same-shape array of True/False, which numpy treats as 1/0 when multiplied. Wherever a hidden unit was "off" (negative Z1) during the forward pass, its gradient is zeroed here — that unit contributed nothing to the output, so it gets no blame and no credit.

The distinction worth internalizing

Backprop through a linear layer (matmul) mixes gradients across units — every output unit's gradient depends on a weighted combination of others via W2.T. Backprop through an element-wise activation never mixes anything — each unit's gradient only ever depends on itself. Keep these two kinds of step visually distinct in your head (and in your code, @ vs *) or shape bugs get much harder to spot.

Step 3 — finish it: dZ1 → dW1, db1

Exactly the same pattern as Lesson 4's output layer, one layer earlier — Z1 = X @ W1 + b1:

dW1 = X.T @ dZ1        # (n_in, batch) @ (batch, n_hidden) -> (n_in, n_hidden)
db1 = dZ1.sum(axis=0)  # broadcast forward -> sum backward, shape (n_hidden,)

The complete backward pass

Chained together, here is the whole thing, output to input — notice it's a mirror image of the forward pass, run in reverse:

dZ2 = (P - Y) / batch
dW2 = A1.T @ dZ2
db2 = dZ2.sum(axis=0)

dA1 = dZ2 @ W2.T
dZ1 = dA1 * (Z1 > 0)
dW1 = X.T @ dZ1
db1 = dZ1.sum(axis=0)

Four gradients — dW1, db1, dW2, db2 — one for every parameter in the network. That's everything gradient descent needs for a single training step.

Primary source Neural Networks and Deep Learning, Chapter 2 — "The four fundamental equations behind backpropagation" Nielsen's equation BP2 is exactly the two steps you just derived (through the weights, then element-wise through the activation's derivative), written for a general activation function σ rather than ReLU specifically. Worth reading now that you've derived the ReLU case by hand — the general pattern will be obvious.

Your tangible win

Extend code/backprop.py from Lesson 4 with the rest of the backward pass, and verify every gradient's shape against its parameter:

# ...continuing from Lesson 4's dZ2, dW2, db2...

dA1 = dZ2 @ W2.T
dZ1 = dA1 * (Z1 > 0)
dW1 = X.T @ dZ1
db1 = dZ1.sum(axis=0)

assert dW1.shape == W1.shape
assert db1.shape == b1.shape
assert dW2.shape == W2.shape
assert db2.shape == b2.shape
print("all gradient shapes match — backward pass is structurally correct")

Then try one experiment: set every entry of Z1 to a large negative number before computing dZ1 (simulating a hidden layer that's "dead" — always off) and print dZ1. It should be all zeros. This is a real phenomenon called a dead ReLU: once a unit's Z1 is permanently negative, its gradient is permanently zero and it stops learning entirely. Worth knowing before it happens to you during real training.

Check your understanding

1. Why is dZ1 = dA1 * (Z1 > 0) written with * instead of @?

2. A hidden unit had Z1 < 0 for every example in the batch. What is its row in dW1?

3. dZ2 is (batch, n_out), W2 is (n_hidden, n_out). Why dZ2 @ W2.T and not dZ2 @ W2?
