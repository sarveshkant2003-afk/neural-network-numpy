Backpropagation, Part 1: The Output Layer

You can compute the loss. Now you need to know how the loss changes as each weight changes — the gradient — so gradient descent knows which direction to push every number in the network. Backprop is just the chain rule, applied methodically from the output backward. This lesson derives it by hand for the output layer; Lesson 5 pushes it through the hidden layer.

Setup: what we're differentiating

Recall the full forward pass from Lessons 2 & 3:

Z1 = X @ W1 + b1
A1 = relu(Z1)
Z2 = A1 @ W2 + b2
P  = softmax(Z2)
L  = cross_entropy(P, Y)

We want ∂L/∂W2 and ∂L/∂b2 — how the loss responds to each entry of the output layer's weights and bias. Gradient descent will later use these to update them. Getting there means threading the chain rule through cross_entropy and softmax at once.

The key derivation: ∂L/∂Z2

This is the one worth doing by hand, because the answer is surprisingly clean and every deep learning framework relies on it. Work with a single example first (indices i, k range over classes); we'll batch it at the end.

Softmax: pk = exp(zk) / ∑j exp(zj). Its derivative w.r.t. its own input has two cases, depending on whether you're differentiating a probability with respect to its own logit or a different one:

Try it yourself first: quotient rule on p_k w.r.t. z_i (k = i case), then reveal

p_k = exp(z_k) / S where S = ∑j exp(z_j). When k = i, both the numerator and S (via its exp(z_i) term) depend on z_i — quotient rule applies. When k ≠ i, only S depends on z_i.

Result:

∂p_k/∂z_i = p_k(1 - p_i)   if k = i
∂p_k/∂z_i = -p_k p_i       if k ≠ i

# both cases in one line, using the Kronecker delta δ_ki (1 if k=i else 0):
∂p_k/∂z_i = p_k(δ_ki - p_i)

Now the loss itself: L = -∑k y_k log(p_k). Chain rule through log and the softmax derivative above:

∂L/∂z_i = -∑_k y_k (1/p_k) · ∂p_k/∂z_i
           = -∑_k y_k (1/p_k) · p_k(δ_ki - p_i)
           = -∑_k y_k (δ_ki - p_i)
           = -y_i + p_i · ∑_k y_k

Since y is one-hot, ∑k y_k = 1. That collapses the whole thing to:

∂L/∂z_i = p_i − y_i

The gradient of cross-entropy-after-softmax, with respect to the pre-softmax logits, is just predicted minus actual. All the exponentials and the quotient rule cancel out completely. This is why softmax and cross-entropy are almost always used together — the combination is not just convenient, it's unusually clean to differentiate.

1. For a single example, what is ∂L/∂z_i in terms of the predicted probability p_i and true label y_i?

For a batch, this holds per row. In matrix form, with P and Y both (batch, n_out), and averaging the loss over the batch (as cross_entropy does with np.mean):

dZ2 = (P - Y) / batch   # shape (batch, n_out) -- same shape as Z2

From ∂L/∂Z2 to ∂L/∂W2 and ∂L/∂b2

Recall Z2 = A1 @ W2 + b2. Rather than re-deriving from scalar calculus, use a technique that will save you constantly: shape reasoning. The gradient of any quantity always has the same shape as that quantity. So work out what matrix multiplication of the pieces you already have must produce the right shape — it pins the answer down almost uniquely.

QuantityShape
A1(batch, n_hidden)
W2, and therefore dW2(n_hidden, n_out)
dZ2(batch, n_out)
Try it yourself first: what combination of A1, dZ2 (and transposes) gives shape (n_hidden, n_out)? Then reveal

Only one arrangement of a matmul between something built from A1 (shape (batch, n_hidden)) and something built from dZ2 (shape (batch, n_out)) produces (n_hidden, n_out):

dW2 = A1.T @ dZ2
# (n_hidden, batch) @ (batch, n_out) -> (n_hidden, n_out)  ✓

This matches the true calculus derivation (each entry dW2[h, o] really is ∑_batch A1[batch, h] · dZ2[batch, o]) — shape reasoning got you there without redoing the chain rule by hand.

For b2, recall from Lesson 2 that + b2 broadcasts the same bias across every row of the batch. Broadcasting forward means the same value was reused batch times; the gradient has to account for all of those uses, which means summing backward over exactly the axis that was broadcast:

db2 = dZ2.sum(axis=0)   # shape (n_out,) -- same shape as b2

This is a general rule worth keeping: broadcasting forward becomes summation backward, over the broadcast axis. You'll use it again for b1 in Lesson 5.

Your tangible win

In code/backprop.py, rebuild the toy 4 → 5 → 3 forward pass from Lessons 2–3, then compute the output-layer gradients:

import numpy as np
np.random.seed(0)

def relu(Z): return np.maximum(Z, 0)
def softmax(Z):
    shifted = Z - Z.max(axis=1, keepdims=True)
    exp = np.exp(shifted)
    return exp / exp.sum(axis=1, keepdims=True)

batch, n_in, n_hidden, n_out = 8, 4, 5, 3
X  = np.random.randn(batch, n_in)
W1 = np.random.randn(n_in, n_hidden) * 0.1
b1 = np.zeros(n_hidden)
W2 = np.random.randn(n_hidden, n_out) * 0.1
b2 = np.zeros(n_out)

Z1 = X @ W1 + b1
A1 = relu(Z1)
Z2 = A1 @ W2 + b2
P  = softmax(Z2)

true_classes = np.random.randint(0, n_out, size=batch)
Y = np.zeros((batch, n_out))
Y[np.arange(batch), true_classes] = 1

# --- backward pass, output layer ---
dZ2 = (P - Y) / batch
dW2 = A1.T @ dZ2
db2 = dZ2.sum(axis=0)

print("dZ2 shape:", dZ2.shape, "  (should match Z2:", Z2.shape, ")")
print("dW2 shape:", dW2.shape, "  (should match W2:", W2.shape, ")")
print("db2 shape:", db2.shape, "  (should match b2:", b2.shape, ")")

Every printed shape should match its corresponding parameter's shape exactly — that's not a coincidence, it's the sanity check shape reasoning gives you for free, every time you write a new gradient.
