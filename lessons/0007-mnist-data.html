Lesson 7 · Neural Networks from Scratch

Real Data: Loading MNIST

Everything so far has trained on made-up toy data — good for testing that the code works, not much else. This lesson swaps it for the real thing: seventy thousand actual images of handwritten digits. Next lesson, you'll train your network on it for real and see how well it can learn to read handwriting.

What MNIST actually is

MNIST is a set of 70,000 small grayscale pictures of handwritten digits, 0 through 9, each one 28 pixels wide and 28 pixels tall. Each pixel is just a number from 0 (black) to 255 (white).

Your network doesn't take a 2D grid as input — it takes a flat row of numbers, same as every example so far. So each image gets "flattened": the 28×28 grid of 784 pixels is unrolled into one long row of 784 numbers. You lose the 2D layout, but that's fine — a plain feedforward network never used the 2D layout anyway; it treats every pixel as just another input number.

Getting it onto your machine

If you don't have it yet: pip install scikit-learn. Then, two lines:

from sklearn.datasets import fetch_openml

X, y = fetch_openml('mnist_784', version=1, return_X_y=True, as_frame=False)

The first time you run this, it downloads about 50MB and can take a minute or two. After that, it's cached on disk and loads instantly. If it fails (no internet, a flaky connection), the alternative is from tensorflow.keras.datasets import mnist then mnist.load_data() — this only uses Keras as a data downloader, nothing about the network itself changes.

Check what you got:

print(X.shape)   # (70000, 784) -- 70000 images, 784 pixels each
print(y.shape)   # (70000,)
print(y[:5])      # labels come back as strings: '5' '0' '4' '1' '9'

y = y.astype(int)   # turn '5' into 5, so we can do math with it

Two things to do before training on it

1. Scale the pixel values down

Pixels range from 0 to 255. That's a wide range of fairly large numbers, and large numbers cause trouble — remember from Lesson 1 why weights were initialized small (* 0.1), and why softmax subtracts the max before exp in Lesson 2? Same reason here: keep the numbers flowing through the network small and well-behaved. One line fixes it:

X = X / 255.0   # every pixel now between 0.0 and 1.0

2. Hold some data back for testing

This is a genuinely new idea, worth sitting with. Imagine a student who studies for a test by memorizing the answer key instead of understanding the material. They'll ace that exact test — but hand them a slightly different set of questions on the same topic, and they fall apart. They never actually learned anything.

A network can do the same thing: given enough capacity, it can just memorize all 70,000 images instead of learning to recognize digits in general. The only way to catch this is to check its accuracy on images it has never seen during training. So before training starts, you set aside a chunk of the data — called the test set — and never let the network learn from it. You only look at test accuracy at the very end.

rng = np.random.default_rng(0)
shuffle = rng.permutation(len(X))
X, y = X[shuffle], y[shuffle]

n_test = 10000
X_train, X_test = X[:-n_test], X[-n_test:]
y_train, y_test = y[:-n_test], y[-n_test:]

print(X_train.shape, X_test.shape)   # (60000, 784) (10000, 784)

Shuffling first matters — MNIST's labels aren't randomly ordered in the raw file, so slicing without shuffling could hand you a test set that's mostly one digit.

One-hot encode the training labels

Same move as Lesson 3, just at real scale:

Y_train = np.zeros((len(y_train), 10))
Y_train[np.arange(len(y_train)), y_train] = 1

The test labels (y_test) can stay as plain integers — you'll compare them directly against the network's predicted class, no one-hot needed there.

Primary source Neural Networks and Deep Learning, Chapter 1 — "The MNIST data set" section Nielsen explains what MNIST is and why it's split into training and test (he even adds a third "validation" split, worth knowing about but not needed yet). For the loading code itself, the reference is the scikit-learn fetch_openml docs.

Your tangible win

Create code/load_mnist.py, put all of the above together, and then look at your data — a habit worth building before training on anything. If you don't have it: pip install matplotlib.

import numpy as np
import matplotlib.pyplot as plt
from pathlib import Path
from sklearn.datasets import fetch_openml

X, y = fetch_openml('mnist_784', version=1, return_X_y=True, as_frame=False)
y = y.astype(int)
X = X / 255.0

rng = np.random.default_rng(0)
shuffle = rng.permutation(len(X))
X, y = X[shuffle], y[shuffle]

n_test = 10000
X_train, X_test = X[:-n_test], X[-n_test:]
y_train, y_test = y[:-n_test], y[-n_test:]

Y_train = np.zeros((len(y_train), 10))
Y_train[np.arange(len(y_train)), y_train] = 1

print("X_train:", X_train.shape, " X_test:", X_test.shape)
print("Y_train:", Y_train.shape, " y_test:", y_test.shape)

# look at a handful of images before trusting any of this
fig, axes = plt.subplots(2, 5, figsize=(8, 4))
for i, ax in enumerate(axes.flat):
    ax.imshow(X_train[i].reshape(28, 28), cmap='gray')
    ax.set_title(str(y_train[i]))
    ax.axis('off')
plt.tight_layout()

out_path = Path(__file__).parent / "mnist_sample.png"
plt.savefig(out_path)
print("saved sample digits to", out_path, "-- open it in VS Code to check")

Run it, then open code/mnist_sample.png in VS Code. Check that every image actually looks like the digit printed above it. This sounds trivial, but it's the single most useful debugging habit in this whole mission — a mislabeled or misshapen dataset will silently sabotage every lesson from here on, and a 30-second look at the images catches it instantly.
