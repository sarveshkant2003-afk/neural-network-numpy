The Forward Pass: Stacking Layers

In Lesson 1 you computed one layer for one example. A real network is several of those chained together, run on a whole batch at once. Before we chain anything, let's make broadcasting — the mechanism that makes batching possible without writing loops — fully solid.

Broadcasting, in detail

The rule from Lesson 1, restated precisely: to combine two arrays, align their shapes from the right. Pad any missing dimensions on the left with 1. Then, dimension by dimension, they're compatible if they're equal, or if one of them is 1 — in which case the size-1 side is (conceptually) repeated to match. If neither condition holds for some dimension, numpy raises an error instead of guessing what you meant.

A reliable three-step way to reason about any broadcast before you run it:

  1. Write both shapes, right-aligned. Pad the shorter one with 1s on the left.
  2. Check each column. Equal, or one is 1 → compatible. Otherwise → error.
  3. The result shape is the elementwise max of the two (padded) shapes.

Worked example 1 — scalar with anything

a = np.array([[1., 2.], [3., 4.]])   # shape (2, 2)
a * 10                                # shape ()  padded -> (1, 1) -> (2, 2)

A scalar has shape (). Padded to match, it's (1, 1) — 1 in every dimension, so it stretches to fit anything. This is why a * 10 just works.

Worked example 2 — bias added to a batch (row-wise)

Z = np.random.randn(32, 5)   # 32 examples, 5 features each
b = np.zeros(5)              # shape (5,)

Z + b
StepShape A (Z)Shape B (b)
1. Right-align, pad(32, 5)(1, 5)
2. Compare column-by-column32 vs 1 → ok (one is 1).   5 vs 5 → ok (equal).
3. Result(32, 5) — b is added to every one of the 32 rows

Worked example 3 — a column vector (column-wise)

Z = np.random.randn(32, 5)
row_max = Z.max(axis=1, keepdims=True)   # shape (32, 1)

Z - row_max

row_max has shape (32, 1). Aligned against (32, 5): 32 vs 32 matches, 1 vs 5 — the 1 stretches. Result: (32, 5), where each row had its own max subtracted. This exact pattern — reduce with keepdims=True, then broadcast back — is how softmax normalizes each row independently, which you'll use below.

Drop keepdims=True and row_max becomes shape (32,) instead of (32, 1) — which right-aligns against (32, 5) as (1, 32), and 32 vs 5 is not compatible. This is the single most common broadcasting bug: forgetting keepdims=True after a reduction.

Worked example 4 — two vectors, outer broadcast

col = np.array([[1.], [2.], [3.]])   # shape (3, 1)
row = np.array([[10., 20.]])          # shape (1, 2)

col + row   # shape (3, 2) -- every pairwise sum, no loop

Neither side is the "bigger" array here — both stretch, one along each axis, producing every pairwise combination. This looks surprising the first time you see it, but it's the same rule applied twice.

Worked example 5 — where it fails

Z = np.random.randn(32, 5)
v = np.random.randn(4)

Z + v   # ValueError: operands could not be broadcast together
        # shapes (32,5) (4,) -- 5 != 4, and neither is 1

Nothing subtle here — it's a genuine shape mismatch, and broadcasting correctly refuses to guess. When you hit this error while building the network, the fix is almost always to print both shapes and apply the three-step check above.

One more thing worth knowing: broadcasting never copies the smaller array in memory. Numpy just re-uses it in place with a stride trick. That's part of why vectorized, broadcasted code isn't just shorter than a Python loop — it's substantially faster too.

From one layer to a network

Lesson 1 handled one example at a time: z = W @ x + b, with x shape (n_in,) and W shape (n_out, n_in). Training on real data means running a whole batch through at once, so we switch convention slightly:

  • X has shape (batch, n_in) — one row per example.
  • W is stored as (n_in, n_out) — the transpose of Lesson 1's convention — so that X @ W lines up: (batch, n_in) @ (n_in, n_out) → (batch, n_out).
  • b stays shape (n_out,), added to every row via broadcasting (worked example 2, above).
Z = X @ W + b   # (batch, n_in) @ (n_in, n_out) + (n_out,) -> (batch, n_out)

A network is just this, repeated, with the output of one layer becoming the input of the next — and an activation function applied at each step so the whole stack doesn't collapse into one big linear function.

Two activation functions

FunctionUsed forFormula
ReLUhidden layersnp.maximum(Z, 0)
Softmaxoutput layer (classification)see below

Softmax turns a layer's raw output into a probability distribution over classes — exactly what you need for classifying a digit into one of 10 classes:

def softmax(Z):
    # Z shape (batch, n_classes)
    shifted = Z - Z.max(axis=1, keepdims=True)   # worked example 3, above
    exp = np.exp(shifted)
    return exp / exp.sum(axis=1, keepdims=True)   # each row now sums to 1

Subtracting the row max before exp doesn't change the mathematical result (it cancels out in the division) but prevents np.exp from overflowing on large inputs. Notice it's the exact broadcasting pattern from worked example 3.

Primary source Neural Networks and Deep Learning, Chapter 1 — Michael Nielsen Read "The architecture of neural networks" through the feedforward computation. Nielsen uses sigmoid neurons and column-vector notation rather than the batched-row convention above — worth noticing the difference, not worth getting hung up on it. The underlying computation is the same.

Your tangible win

Create code/network_forward.py. Build a tiny two-layer network — 4 → 5 → 3 — and run a batch of 8 random examples through it end to end:

import numpy as np
np.random.seed(0)

def relu(Z):
    return np.maximum(Z, 0)

def softmax(Z):
    shifted = Z - Z.max(axis=1, keepdims=True)
    exp = np.exp(shifted)
    return exp / exp.sum(axis=1, keepdims=True)

batch, n_in, n_hidden, n_out = 8, 4, 5, 3

X  = np.random.randn(batch, n_in)
W1 = np.random.randn(n_in, n_hidden) * 0.1
b1 = np.zeros(n_hidden)
W2 = np.random.randn(n_hidden, n_out) * 0.1
b2 = np.zeros(n_out)

A1 = relu(X @ W1 + b1)        # layer 1
probs = softmax(A1 @ W2 + b2)  # layer 2 (output)

print("X shape:", X.shape)
print("A1 shape:", A1.shape)
print("probs shape:", probs.shape)
print("row sums (should all be ~1.0):", probs.sum(axis=1))

Before running it, predict A1.shape and probs.shape from the matmul rule. Then run it and check that every row of probs sums to (approximately) 1 — that's the broadcasting in softmax working correctly, and it's exactly the shape this network will need for MNIST, just swap 4 → 5 → 3 for 784 → 128 → 10.
