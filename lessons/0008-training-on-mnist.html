Sizing the network

The input and output sizes aren't a choice — they're fixed by the data. Only the hidden layer size is up to you:

LayerSizeWhy
Input784one number per pixel — fixed by the data
Hidden128your choice — enough room to learn useful patterns, not so much it's slow
Output10one per digit, 0 through 9 — fixed by the task

128 isn't derived from anything — it's a well-tested default that works fine here. If you're curious later, try 32 or 256 and see what changes.

A small but important fix to weight initialization

Every layer so far used randn(...) * 0.1 for its starting weights. That was fine with 4 inputs. With 784 inputs feeding into one hidden neuron, it isn't: that neuron sums up 784 numbers, each already a small random weight times a pixel value. Even small values, added 784 times, can land far from zero — pushing the neuron's output to an extreme before training has even started.

The fix is simple: the more inputs a neuron has, the smaller each individual weight should be, so their sum stays in a reasonable range. Scale by 1/sqrt(number of inputs) instead of a fixed number:

def init_weights(n_in, n_out, rng):
    return rng.standard_normal((n_in, n_out)) * np.sqrt(1.0 / n_in)

If you search for this later, it's a simplified version of what's usually called Xavier or He initialization. You don't need the full theory to use the one-line version above — just the intuition that more incoming connections means each one should start smaller.

Mini-batches: training in smaller chunks

Every training step so far has run the entire dataset through the network before updating once. With 60,000 images that still works, but it means only one update per full pass through the data — slow progress.

The standard fix: instead of one giant batch of 60,000, split the data into many small batches — say, 128 images each — and update the weights after every small batch. One full pass through all the data (now made of many small batches) is called an epoch. You get roughly 470 updates per epoch instead of 1, so the network improves much faster in the same amount of time.

def iterate_batches(X, Y, batch_size, rng):
    n = X.shape[0]
    order = rng.permutation(n)          # new random order each epoch
    for start in range(0, n, batch_size):
        idx = order[start:start + batch_size]
        yield X[idx], Y[idx]

Nothing about the forward pass, loss, or backward pass changes — a batch of 128 flows through exactly the same code as a batch of 8 did in Lesson 6. Only the size of batch changes, and everything you wrote already handles that correctly, because it was never hardcoded to a specific size.

Epoch, unpacked

Think of the 60,000 training images as a stack of flashcards. An epoch is one full pass through that entire stack, once. With a batch size of 128, one epoch is made of about 469 small batches (60,000 ÷ 128), and each batch triggers one weight update. So "8 epochs" doesn't mean 8 updates — it means the network sees every image 8 separate times (in a freshly shuffled order each time), with roughly 469 updates happening within each pass. Over 8 epochs that's around 3,750 total updates to the weights.

How long will this actually take?

Two very different phases:

  • Loading the data (one-time): fetch_openml downloads about 50MB the first time you run it — usually 30 seconds to a couple of minutes, depending on your connection. After that it's cached on disk and loads in a couple seconds.
  • Actual training (8 epochs): this is small matrix math, and numpy is fast at it. On a normal modern laptop, expect well under a minute total — but the honest answer is "it depends on your machine," which is exactly why the script below prints its own timing instead of asking you to guess.

Your tangible win — the mission target

Create code/train_mnist.py. It's Lesson 7's loading code, Lesson 6's training loop, and the two changes above, combined:

import time
import numpy as np
from sklearn.datasets import fetch_openml

def relu(Z):
    return np.maximum(Z, 0)

def softmax(Z):
    shifted = Z - Z.max(axis=1, keepdims=True)
    exp = np.exp(shifted)
    return exp / exp.sum(axis=1, keepdims=True)

def cross_entropy(P, Y, eps=1e-12):
    P = np.clip(P, eps, 1 - eps)
    return np.mean(-np.sum(Y * np.log(P), axis=1))

def init_weights(n_in, n_out, rng):
    return rng.standard_normal((n_in, n_out)) * np.sqrt(1.0 / n_in)

def iterate_batches(X, Y, batch_size, rng):
    n = X.shape[0]
    order = rng.permutation(n)
    for start in range(0, n, batch_size):
        idx = order[start:start + batch_size]
        yield X[idx], Y[idx]

# --- load and prepare the data (Lesson 7) ---
X, y = fetch_openml('mnist_784', version=1, return_X_y=True, as_frame=False)
y = y.astype(int)
X = X / 255.0

rng = np.random.default_rng(0)
shuffle = rng.permutation(len(X))
X, y = X[shuffle], y[shuffle]

n_test = 10000
X_train, X_test = X[:-n_test], X[-n_test:]
y_train, y_test = y[:-n_test], y[-n_test:]

Y_train = np.zeros((len(y_train), 10))
Y_train[np.arange(len(y_train)), y_train] = 1

# --- set up the network ---
n_in, n_hidden, n_out = 784, 128, 10
W1 = init_weights(n_in, n_hidden, rng)
b1 = np.zeros(n_hidden)
W2 = init_weights(n_hidden, n_out, rng)
b2 = np.zeros(n_out)

lr = 0.5
batch_size = 128
epochs = 8

# --- train, with a timer so you can see how long each epoch (and the whole run) takes ---
training_start = time.time()

for epoch in range(epochs):
    epoch_start = time.time()

    for Xb, Yb in iterate_batches(X_train, Y_train, batch_size, rng):
        Z1 = Xb @ W1 + b1
        A1 = relu(Z1)
        Z2 = A1 @ W2 + b2
        P  = softmax(Z2)

        n = Xb.shape[0]
        dZ2 = (P - Yb) / n
        dW2 = A1.T @ dZ2
        db2 = dZ2.sum(axis=0)
        dA1 = dZ2 @ W2.T
        dZ1 = dA1 * (Z1 > 0)
        dW1 = Xb.T @ dZ1
        db1 = dZ1.sum(axis=0)

        W1 -= lr * dW1; b1 -= lr * db1
        W2 -= lr * dW2; b2 -= lr * db2

    # check progress once per epoch, on the full training set
    A1_full = relu(X_train @ W1 + b1)
    P_full  = softmax(A1_full @ W2 + b2)
    loss = cross_entropy(P_full, Y_train)
    acc  = (P_full.argmax(axis=1) == y_train).mean()

    epoch_time = time.time() - epoch_start
    print(f"epoch {epoch+1}/{epochs}  loss {loss:.4f}  train acc {acc:.3f}  ({epoch_time:.1f}s)")

total_time = time.time() - training_start
print(f"\ntraining finished in {total_time:.1f}s total ({total_time/epochs:.1f}s/epoch average)")

# --- the moment of truth: accuracy on data the network never saw ---
A1_test = relu(X_test @ W1 + b1)
P_test  = softmax(A1_test @ W2 + b2)
test_acc = (P_test.argmax(axis=1) == y_test).mean()
print(f"\nfinal test accuracy: {test_acc:.3f}")

Run it. It'll take a few minutes (training happens locally on your CPU). Watch the loss fall and accuracy climb, epoch by epoch — then look at the final line. A working implementation typically lands somewhere in the low-to-mid 90s% test accuracy. If you get a number in that range, you've built and trained a real neural network from nothing but numpy.
